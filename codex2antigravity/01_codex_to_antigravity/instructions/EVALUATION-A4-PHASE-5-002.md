2. **PRM3-04: pipeline omits its own catalog/policy gates, and valid policy input is rejected.** `validate-manifest` checks registration only when optional `--catalog` is supplied, but `Jenkinsfile.release` never supplies it. The stage can accept an unregistered manifest. `evaluate-security` runs the policy only when optional `--policy-input` is supplied, which the pipeline also omits. Moreover the CLI compares `ReleaseSecurityDecision.decision` with `"APPROVED"`, although the contract returns `"PASS"` or `"FAIL"`; direct clean-policy probe produced `PASS` and CLI exit 2 (`Release security policy rejected release: []`). Make catalog registration and policy evaluation mandatory for a release pipeline execution, compare the actual typed decision values, and bind app/release/manifest/component identities to the validated report. Use `load_registered_manifest` for catalog integrity rather than manual partial entry parsing. Wire the required paths through the shared library and Jenkinsfile, with positive and negative tests. 3. **PRM3/4-05: dry-run eligibility and file safety overclaim.** Dry-run `cmd_promote_release` checks only terminal FSM state, then returns `success=true` and says the release is eligible; it does not run the registered-manifest, report, environment-sequence, or governance preflight from `promote_release`. Keep `SIMULATED` and `fsm_promoted=False`, but report a plan as eligible only after the same read-only preflight as execution; otherwise return a denied plan. `resolve_safe_path` calls `resolve()` before checking `is_symlink()` on path segments, so a symlink within the workspace can be hidden by resolution; the root is also resolved before its symlink check. Inspect lexical segments before resolution, then enforce containment. On this Windows host symlink creation returned WinError 1314, so add a deterministic mock fallback alongside a real-symlink test where supported. Output handlers use `allow_overwrite=True` and direct `write_text`; make evidence/report writes atomic and reject or safely handle pre-existing files. Do not overwrite untrusted evidence.
